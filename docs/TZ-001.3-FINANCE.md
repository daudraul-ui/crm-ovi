# CRM OVI — TASK 001.3
## Единый финансовый модуль: БДР, ДДС, общехозяйственные и прямые затраты
**Статус:** консолидированное ТЗ по утверждённым решениям, подготовлено к реализации.  
**Дата:** 12.11.2026.  
**Репозиторий:** daudraul-ui/crm-ovi.  
**Смежные работы:** TASK 001.2, БП-01, БП-02.  
**Приоритет:** простое использование без дублирования сущностей и сложного бухгалтерского функционала.

> Это управленческий учёт. Модуль не заменяет 1С/регламентированный бухгалтерский и налоговый учёт. Не изменять согласованные правила БП-01/02 и исходную маржу утверждённого КП. Реализация ещё не подтверждена; документ описывает требования.

## 1. Цель и границы
Одна система для: выручки и прямых затрат по реализованным партиям оборудования/магазинам/этапам монтажа; валовой прибыли; ОХР и их ежедневного аналитического распределения по проектам; операционной прибыли; плана и факта БДР; ДДС с частичными оплатами и банковскими выписками; закрытия месяца с сохранением версий.

Не создавать вторую независимую модель экономики проекта. Использовать связи уже существующих клиентов, проектов, магазинов, заказов, поставок, документов и платежей, когда эти сущности реализованы. Если сущности отсутствуют, предусмотреть минимальные интеграционные модели, не дублирующие БП-01/02. Никакого автоматического merge/deploy.

## 2. Утверждённые бизнес-правила (обязательные)
1. Единый БДР компании: выручка − прямые затраты = валовая прибыль; валовая прибыль − ОХР = операционная прибыль (прочие будущие статьи учитывать отдельно).
2. ОХР признаются в БДР ровно один раз; отдельно аналитически распределяются по проектам, не создавая повторного расхода компании.
3. ОХР распределяются **каждый календарный день поровну между проектами, активными в этот день**, затем суммируются по календарному месяцу. Нераспределённая доля дней без активных проектов остаётся в БДР компании. История статусов проектов обязательна для воспроизводимости. Изменения закрытого месяца — только через корректировку и новую версию аналитики.
4. Статьи БДР: **раздел → группа → статья**, независимо от них — справочник **центров затрат**.
5. Для офисного имущества нет стоимостного порога. На каждую покупку вручную выбирается единовременное признание, постепенное признание с графиком или ожидание классификации. Управленческая модель не объявляется бухгалтерской амортизацией.
6. **Все ОХР утверждает только директор**, независимо от статьи/суммы. Изменение существенных реквизитов утверждённой записи — повторное согласование или корректировка; исходную запись сохранять.
7. БДР и ДДС раздельные. В ДДС платежи по дате движения денег, допускается частичная оплата, несколько платежей на один расход и распределение одного платежа на несколько расходов. Оплата не дублирует расход БДР.
8. Регистрация платежей: вручную с документом и импорт банковской выписки (Excel/CSV); автоматическое сопоставление по устойчивым идентификаторам и реквизитам. Однозначные платежи выписки подтверждаются автоматически; остальные — уполномоченный сотрудник; спорные — директор. Не подтверждать только по совпадению суммы. Не создавать повторные платежи из повторного импорта. Собственные переводы — не расходы; корректно обрабатывать возвраты.
9. Бюджет версионный: первоначальный утверждённый директором план неизменяем; изменение через новую версию, утверждённую директором. Видны первоначальный план, актуальный план, факт, отклонения.
10. Перерасход бюджета: предупреждение по статье/центру затрат/месяцу, сумма и процент. Директор может утвердить расход без изменения бюджета с обязательным объяснением; план сохраняется.
11. Месяц закрывает директор с фиксацией БДР, ДДС и распределения ОХР. Поздние документы/ошибки — только отдельными согласованными корректировками и новой версией отчёта. Исходное закрытие неизменно.
12. Выручка по оборудованию и монтажу признаётся **раздельно**, с частичной реализацией. Учитывать соответствующие УПД/передачи оборудования и акты/подтверждения монтажа, в зависимости от документированной реализации. Авансы не являются выручкой БДР.
13. Прямые затраты признаются **вместе с соответствующей реализацией** оборудования, партии, магазина либо этапа монтажа. Платеж поставщику относится к ДДС. Пока соответствующая реализация отсутствует — затрата участвует в прогнозе и учёте незавершённого, но не удваивает факт БДР.
14. Общие прямые затраты в рамках проекта распределяются **для каждой затраты отдельным выбранным способом**: поровну; пропорционально закупочной себестоимости; пропорционально выручке; вручную. Сумма распределения должна точно сходиться до копейки. Без базы распределения автоматическую цифру не подставлять. Это НЕ метод распределения ОХР.
15. При реализации без окончательных документов поставщика допускается **временная оценочная себестоимость** только по письменно подтверждённой стоимости. После УПД/акта — сверка и, при необходимости, корректировка только на разницу; не удваивать себестоимость. Различать «оценочная» и «подтверждена документом».
16. Корректировку прямой себестоимости создаёт ответственный менеджер проекта или уполномоченный финансовый сотрудник. В открытом периоде порог по **модулю накопленного отклонения актуальной суммы от первоначальной подтверждённой оценки**: до **30 000 ₽ включительно — РОП**, более 30 000 ₽ — директор. За закрытый период **любую** корректировку утверждает директор. Дробление изменений не обходит лимит. Уменьшение и увеличение проверяются одинаково.
17. Предварительная корректировка прямой себестоимости возможна по письменному подтверждению поставщика до окончательной первички, с сохранением оценочного статуса и обязательной последующей сверкой.
18. Срок получения окончательного документа: приоритет **заказ → поставщик → общий срок по умолчанию**. Конкретное число рабочих дней по умолчанию пока НЕ утверждено; сделать конфигурируемым, не выдумывать значение. Один контрольный срок, одно напоминание о просрочке без усложнённых цепочек.
19. Закрытие при наличии оценочных затрат: показывать директору предупреждение и перечень неподтверждённых сумм; закрытие не блокировать только по этому основанию (упрощённое проектное правило, зафиксированное при сокращении сложности).
20. Исходная маржа согласованного КП меняется только при согласованных изменениях клиента в цене, объёме или составе. Внутренние перерасходы и аналитическое распределение ОХР изменяют прогноз/факт и показатели полной рентабельности, **не исходную маржу КП**.

## 3. Минимальные экраны (без перегрузки)
1. **Финансы → БДР**: период, центр затрат, иерархия раздел/группа/статья, исходный план, актуальный план, факт, отклонение, валовая/операционная прибыль; детализация до документов.
2. **Финансы → Расходы**: единый реестр с фильтрами по периодам, категории, центру затрат, проекту и статусу; карточка расхода с документами, НДС, способом признания и утверждением.
3. **Финансы → Платежи / ДДС**: реальные платежи, частичные оплаты, остатки, импорт банковских выписок с предварительным просмотром и очередью спорных совпадений.
4. **Финансы → Бюджет**: версии плана и утверждение директором, история поправок.
5. **Финансы → Закрытие месяца**: свод БДР/ДДС, оценочная себестоимость, отклонения, нераспределённые ОХР; кнопка закрытия директором, просмотр версий и корректировок.
6. **Карточка проекта → Финансы**: выручка, план/прогноз/факт прямой себестоимости, валовая прибыль, аналитически распределённые ОХР, прибыль после ОХР, привязанные реализации, этапы и документы.

Возможны вкладки вместо отдельных страниц. Не создавать избыточные экраны и статусы; понятный русский интерфейс, поиск, фильтры, Excel-экспорт.

## 4. Данные и связи
**Статья БДР:** код, раздел/группа/статья, активность. **Центр затрат:** название, активность. **Бюджет/версия:** период, автор, дата, статус, утверждение директора, неизменяемые строки планов по статье и центру.

**Расход/начисление:** источник (прямой или ОХР), проект (для прямого), поставщик/контрагент, договор/заказ/документ, статья, центр затрат, сумма без НДС, НДС, сумма с НДС, валюта, период/график признания, план/оценка/факт, статус документов, автор, утверждающий, комментарий, ссылки на файлы, аудит. Для признания использовать согласованную управленческую базу без НДС или с НДС по настраиваемой политике — правило выбора ещё требует подтверждения (см. «Открытые решения»).

**Реализация:** проект, магазин, партия, позиция/этап, категория «оборудование/монтаж», количество, дата, стоимость, документ-основание, возвраты/исправления. Связь «затрата ↔ реализация» допускает частичные суммы/позиции; нельзя превысить доступную стоимость.

**Платёж:** счёт/касса, дата, сумма, валюта, направление, контрагент, банковский идентификатор операции, назначение, первичный документ, подтверждение/источник, аллокации на обязательства, журнал сверки. Для собственных переводов отдельная классификация.

**Распределение ОХР:** дата, общая сумма за день, список активных проектов, суммы/доли до копейки, ссылка на версию месячного закрытия; история статусных интервалов. Правило округления: суммы по проектам плюс нераспределённый остаток = ОХР соответствующего дня/месяца.

**Корректировка:** первичный объект, первоначальная оценка, утверждённая текущая сумма, предложенная сумма, накопленное отклонение, причина, подтверждающий документ, период, автор, утверждающий, статус; разница в БДР только после утверждения.

Вместо дублирования документов/проектов использовать существующие модельные связи, не ломая миграции TASK 001.2 и БП-01/02.

## 5. Операционные сценарии
**Покупка офисной техники:** сотрудник создаёт расход, выбирает категорию и центр затрат, загружает счёт/акт, вручную выбирает немедленное или периодическое признание; директор утверждает; в БДР начисления попадают по выбранному графику, в ДДС — отдельно по факту платежей. При превышении бюджета директор видит предупреждение и оставляет комментарий.

**Частичная реализация:** отдельно признаются поставка оборудования для конкретного магазина/партии и акт монтажа; прямые затраты соотносятся с соответствующей реализацией. При отсутствии итоговой первички учесть подтверждённую оценку; после получения документа сравнить и исправить только разницу.

**Общая доставка:** одна транспортная затрата относится к нескольким магазинам, выбирается один из четырёх методов распределения; проверка сумм, подтверждение; при частичной реализации затраты признаются пропорционально привязанной реализованной части.

**Банковская выписка:** загрузка CSV/XLSX, предпросмотр, распознавание колонок, дедупликация, однозначные совпадения автоматически, неопределённые — ответственному, спорные — директору. Импорт не должен приводить к автоматическому признанию расхода БДР.

**Закрытие месяца:** директор видит контрольный лист, утверждает снимок; последующая корректировка создаёт новую версию результатов без изменения старой.

## 6. Роли
**Директор:** утверждает все ОХР, версии бюджета, спорные платежи, корректировки прямой себестоимости >30 000 ₽ и любые за закрытый период, закрывает месяц.
**РОП:** утверждает прямые корректировки в открытом периоде при накопленном абсолютном отклонении ≤30 000 ₽.
**Менеджер проекта:** создаёт прямые корректировки в своём проекте; права регистрации ОХР по назначению.
**Финансовый сотрудник с отдельным разрешением:** вводит первичку, затраты, корректировки, ручные платежи и сверку.
**Остальные роли:** по принципу минимальных прав. Права проверять и в UI, и на API; финансовая информация не должна вытекать через отчёты и экспорт.
Вопрос, кому именно выдавать роль финансового сотрудника, решается администратором — не давать автоматически всем менеджерам.

## 7. Простота: что сознательно НЕ включать
Не превращать CRM в бухгалтерскую систему: без плана счетов РСБУ, сложной амортизации и налогового расчёта, многокаскадных процессов согласования каждого документа, постоянного пересчёта старых версий, сложной ежедневной ручной разметки. Одна контрольная дата по первичке, один цикл предварительной оценки → сверки → корректировки. Автоматизация расчётов и предупреждений, ручное решение только при споре/согласовании.

## 8. Критерии приёмки
- Единственный источник начисления: БДР не зависит от даты оплаты и не удваивается при повторном платеже.
- Частичная реализация корректно относит соответствующую себестоимость и не захватывает неотгруженные позиции.
- ОХР отражены один раз в компании; ежедневное равное распределение по активным проектам сводится до копейки; дни без проектов не теряются.
- Подтверждённые банковские выписки не дублируются; частичные платежи и собственные переводы правильно классифицируются.
- Произвольная покупка офисной техники без порога допускает вручную выбранный график признания.
- ОХР утверждает только директор; перерасход допускается только с предупреждением и комментарием директора.
- Бюджетные версии неизменяемы; исходный план не переписывается.
- Корректировки прямых затрат проверяют накопленное отклонение от исходной оценки: 30 000 ₽ включительно РОП, свыше директор, закрытый период всегда директор.
- Письменное подтверждение даёт возможность временной оценки, итоговый документ подтверждает/корректирует ровно разницу.
- Закрытие месяца сохраняет исходные снимки БДР/ДДС/аналитики; поздние изменения только отдельными версиями.
- Сохранены исторические проекты, магазины, сделки, финансовые документы; миграции на копии базы, резервное копирование, PostgreSQL/Compose CI, негативные тесты, отсутствие регрессий в TASK 001.2/БП-01/02.
- Для Codex обязателен отчёт «реализовано/не реализовано/не утверждено», результаты фактически запущенных тестов, инструкция безопасного обновления Codespaces. Не сливать PR #1 в main и не выкатывать в production без указания владельца.

## 9. Открытые решения — НЕ придумывать
1. Общий срок получения первичных документов по умолчанию (в рабочих днях) не установлен. Индивидуальные сроки заказа/поставщика уже согласованы.
2. Конкретные основания статуса «активный проект» для ежедневного распределения (точка отсчёта статуса, включение дня начала/завершения, исторические проекты) должны быть выверены с фактической моделью.
3. Политика сумм БДР при НДС и смешанных режимах НДС; порядок учёта невозмещаемого НДС.
4. Правила валют и курсовых разниц при операциях не в рублях.
5. Полномочия ручной регистрации/подтверждения отдельных платежей, а также выбор конкретных финансовых сотрудников.
6. Точный набор оснований для признания выручки при передаче без подписанного УПД и этапах монтажа.
7. Полный перечень центров затрат и начальная иерархия статей.

Эти вопросы не блокируют проектирование каркаса; рискованные финансовые автоматизации по ним не включать до утверждения.
